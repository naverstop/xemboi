# 관법(觀法) 룰 엔진 설계 — "인수가 식상 만났을 때" 공식의 결정적 적용

작성: 2026-07-06 (할루시 검증 케이스 #4에서 파생) / 상태: **설계 — 승인 대기**

## 1. 배경 (실측 문제)

전문가(현명역학원) 지적: 문서운·매매운·취업운·연애운 질문에 선생님 관법 공식이 적용되지 않음.
- 공식 예: "인수가 식상을 만났을 때 → 문서·계약 지연", "인수가 재와 합되면 → 매매 성사" 류
- 원인 3중: ①공식책(명리전 1권) OCR 파괴로 색인 불능(→vision 재전사로 별도 해결)
  ②질문 어휘("매매운")와 공식 어휘("인수가 재와 합")의 격차로 RAG 검색이 못 이음
  ③공식은 '조건→해석'의 결정적 룰인데 적용을 약한 1차 LLM의 추론에 맡기고 있음

기존 성공 패턴 재사용: 용신 환각 → 조후용신 120칸 결정 모듈(커밋 1be98b10)과 동일 철학
— **조건 판정은 코드가, 해석 서술만 LLM이**.

## 2. 아키텍처 (4개 부품)

```
질문 ─→ [A 주제 라우터] ─→ topic (문서/매매/취업/연애/승진/금전/건강/소송…)
명식+세운/대운 ─→ [B 조건 판정기] ─→ 성립한 십성 관계 집합
topic × 관계 ─→ [C 룰 매처] ─→ 매칭된 관법 룰만 프롬프트 주입("이 공식만 근거로")
답변 ─→ [D 검증기] ─→ 주입 룰과 모순 시 기존 재생성 루프(_correct_branches) 합류
```

### A. 주제 라우터
질문 키워드 → topic 사전 (결정적, JSON로 관리):
`매매|부동산|계약|문서 → document` `취업|이직|합격 → career` `남자친구|여자친구|연애|결혼 → love` …
topic이 안 잡히면 룰 주입 없이 기존 흐름(변화 없음 — 안전한 폴백).

### B. 조건 판정기 (전부 기존 데이터로 계산 가능)
- 십성: `compute_ten_god(일간, X)` — 있음
- 합·충·형·파·해: `STEM_COMBINATIONS`·`BRANCH_*` — constants에 있음
- 스코프: 원국 내 / 세운→원국 / 대운→원국 / 세운→대운
- 산출 예: `{("印", "meets", "食傷", "세운→원국"), ("印", "합", "財", "원국")}`

### C. 룰 스키마 (`data/rag/gwanbeop_rules.json`)
```json
{
  "id": "doc-001",
  "topics": ["document", "realestate"],
  "condition": {"subject": "印", "relation": "합", "object": "財", "scope": "세운→원국"},
  "interpretation": "문서(인수)가 재와 합 — 문서가 돈으로 변함, 매매·계약 성사 방향",
  "source": "세운분석보연 정리 4 p.1",
  "reviewed": false
}
```
- `reviewed: true`(선생님 감수 완료)인 룰만 운영 주입 — "명중해야 신뢰도가 높아진다" 요구 반영
- 상충 룰 공존 허용(조건이 다르면 둘 다 유효); 동일 조건 상충은 감수 단계에서 해소

### D. 프롬프트 주입 + 검증
- 매칭 룰을 `[선생님 관법 — 이 명식에 실제로 성립한 공식]` 블록으로 주입, "이 공식을 풀이의
  뼈대로 삼고, 성립하지 않은 공식을 지어내지 말 것" 지시
- 검증기: 주입 룰의 방향(긍정/부정)과 답변 결론이 정반대면 재생성(케이스 #3 프레임워크 재사용)

## 3. 룰 확보 경로 (3단계)

| 단계 | 방법 | 규모 | 감수 |
|---|---|---|---|
| B1 | 세운분석보연·카톡정리에서 **수동 추출** (구현 검증용) | ~20룰 | 뽀 선생님 |
| B2 | 명리전 1권 vision 재전사본 + 사례 PDF에서 **Claude 배치 초벌 추출** | 100+ | 뽀 선생님 |
| B3 | 감수 UI(관리자 탭에 룰 목록·승인 토글) — 초기엔 스프레드시트 검토로 대체 가능 | — | — |

## 4. 구현 순서 (각 단계 승인 후 진행)

1. **B1**: 스키마 + 조건 판정기 + 룰 매처 + 수동 룰 20개 + 주입 (검증기 제외) — 백엔드만
2. **B2**: Claude 배치 룰 추출 스크립트(야간) + reviewed 게이트
3. **B3**: 검증기(모순→재생성) + 관리자 감수 화면

## 5. 리스크

- 룰 오적용 > 룰 부재: 조건 판정이 확실할 때만 주입(모호하면 주입 안 함 — 오탐 0 지향)
- 선생님 관법이 유파 특수 해석일 수 있음 → tier1 원문과 룰이 충돌해도 **룰(감수본) 우선** 명시
- topic 라우터 미스 → 기존 흐름 폴백이라 현행보다 나빠지지 않음
